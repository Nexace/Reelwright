## 1. HIGGSFIELD

Higgsfield has TWO separate programmatic products. This matters for the connector.

### 1a. Higgsfield API (REST, "developer product")  [VERIFIED]
- Docs: https://docs.higgsfield.ai (index: https://docs.higgsfield.ai/docs/llms.txt), read 2026-11-02.
- Base URL `https://api.higgsfield.ai`. Console for keys: https://console.higgsfield.ai
- Auth: header `Authorization: Key ${HF_API_KEY_ID}:${HF_API_KEY_SECRET}` (https://docs.higgsfield.ai/docs/authentication.md). Legacy `hf-api-key` / `hf-secret` headers still accepted but "new integrations should use the Authorization header". Docs: "Keep the credentials server-side only. They grant access to your account and balance." (quickstart). Doc env var names: `HF_API_KEY_ID`, `HF_API_KEY_SECRET`. Keys are API key ID + secret, not OAuth.
- Submit: `POST https://api.higgsfield.ai/<model-path>` with JSON body that depends on the model. Headers: `Authorization`, `Content-Type: application/json`, and `Idempotency-Key` (recommended; resend the same key after an ambiguous timeout so no duplicate generation).
  - Quickstart example: `POST /higgsfield-ai/soul/v2/standard`, body `{"prompt": "..."}` (https://docs.higgsfield.ai/docs/quickstart.md).
  - OpenAPI (https://docs.higgsfield.ai/docs/openapi.json) lists: `POST /higgsfield-ai/soul/standard` (prompt, num_images 1-4, resolution 2K|4K, aspect_ratio 1:1,4:3,3:4,3:2,2:3,5:4,4:5,16:9,9:16,21:9), `POST /kling-video/v2.5-turbo/{pro,standard}/image-to-video`, `/kling-video/v2.5-turbo/pro/text-to-video`, `/minimax/hailuo-2.3/standard/{image,text}-to-video` (prompt, image_url, duration 5|10 or 6|10, cfg_scale, negative_prompt, prompt_optimizer). The OpenAPI file lags the docs (it lacks soul/v2).
  - Model catalog page (https://docs.higgsfield.ai/docs/models.md) says 84 entries (17 image, 67 video); families named: Genjutsu (motion transfer: `/higgsfield/genjutsu/motion-transfer/v1.0`, takes `video_url` + `image_urls`, source video at least 4 s), Seedance, Kling, Wan, MiniMax, LTX, PixVerse, Grok, SOUL, Recraft, Qwen Image, Ideogram, Z-Image, Cinema Studio. Per-model endpoint/params are on per-model pages and the console, not enumerated. Docs say "Model availability depends on your account" (FAQ) and "individual models may have separate access restrictions" (authentication page).
- Response (async): immediately `{"status":"queued","request_id":"<uuid>","status_url":"https://api.higgsfield.ai/requests/<id>/status","cancel_url":".../cancel","expires_after":604800}`. Docs: "Use the URLs from the response instead of constructing them manually."
- Poll: `GET status_url` with the same Authorization header. Status values: `queued`, `in_progress` (non-terminal); `completed`, `failed`, `nsfw`, `canceled` (terminal) (https://docs.higgsfield.ai/docs/concepts/requests.md). Completed shapes: image -> `images: [{url}]`; video -> `video: {url}`; audio -> `audio: {url}` / `audios: [{url}]`; also `expires_at`, and `error` on failure. Some video/3D ops can return zip, mov, jsx, fbx, ply. Polling interval / backoff guidance is at https://docs.higgsfield.ai/docs/concepts/polling.md (NOT read). Webhooks exist (https://docs.higgsfield.ai/docs/how-to/webhooks.md, NOT read).
- Cancel: `POST cancel_url` -> `202` empty body while queued, `400` after processing started. Delete: `DELETE /requests/{id}` -> `200 {"request_id","status":"deleted"}`, `409` while queued/in_progress.
- Output URLs: files kept "seven days after the request finishes" (`Hf-Expires-After` header can shorten, min 1 hour). "Copy completed media to your own storage" (billing-and-retention page). File formats are model-dependent (image URL example is .jpg); exact format list UNVERIFIED.
- SDKs [VERIFIED, https://docs.higgsfield.ai/docs/how-to/sdk.md]: Python `pip install higgsfield-client` (env `HF_KEY="id:secret"`; `higgsfield_client.subscribe("higgsfield-ai/soul/v2/standard", arguments={...})`); TypeScript `npm install @higgsfield/client` (env `HF_CREDENTIALS`; import `@higgsfield/client/v2`). "Both SDKs are meant for trusted server-side use only." Reelwright should not need an SDK: plain `fetch` covers submit + poll.

### 1b. Higgsfield CLI (official, MIT)  [VERIFIED]
- Repo https://github.com/higgsfield-ai/cli (MIT per README/LICENSE). Install: `npm install -g @higgsfield/cli` | `brew install higgsfield-ai/tap/higgsfield` | curl script. Guide: https://higgsfield.ai/blog/higgsfield-cli and https://higgsfield.ai/creator-hub/help-center/integrations/how-do-i-access-higgsfield-via-cli (read 2026-11-02).
- Auth: `higgsfield auth login` (opens a browser, "No API key needed"; token is "short-lived", re-login on "Session expired"). `higgsfield auth token` prints a token. So it is interactive/browser OAuth, not an env-var key: awkward for CI and for "credentials only from env/ignored file".
- Use: `higgsfield generate create <model_id> --prompt "..." --wait --json` (also `generate cost|get|wait|list`, `model list|get`, `--start-image`, `--duration`, `--resolution`, `--aspect_ratio`, `--wait-timeout` default 10 m, `--wait-interval` default 3 s). `--json` output includes `id, job_type, status, result_url, params`; video adds `medias`, `thumbnail_url`. Model ids from the guide: seedance_2_5, kling3_0, veo3_1, wan3_0, text2image_soul_v2, nano_banana_2, gpt_image_2_5, flux_2 (run `higgsfield model list` for current).
- Billing: "A paid Higgsfield subscription." "Every generation is charged to that account's plan credits at standard rates." "Unlimited model access and free generations do not apply to CLI generations." Guide table: API uses a "Separate prepaid API balance in US dollars" and "does not use your higgsfield.ai plan credits". The CLI guide's example costs: 80 credits (5 s 1080p Seedance 2.5), 15 credits with `--draft true`, "Prices may change".
- Help-center page: "API keys belong to the Higgsfield API, a separate developer product." CLI use "falls under the Developer Terms ... you're responsible for what a coding agent generates through your account."

### 2. Higgsfield plan, rate limits, terms
- Access: API is pay-as-you-go: "The API runs on pay-as-you-go by default: you top up a balance and pay per generation." (https://docs.higgsfield.ai/docs/help/faq.md). Invoice billing only for "customers on a committed-use contract". Docs state no plan/subscription requirement for API keys (authentication page lists none; the how-to page does not mention subscriptions). The CLI, in contrast, needs a paid subscription (above). Enterprise API "gives every account the same endpoints" plus controls (https://docs.higgsfield.ai/docs/enterprise/overview.md).
- Prices: "The exact cost depends on the selected model and parameters." There is an estimate endpoint; the docs' only figure is an illustrative `"usd": "0.094"` shown for format. No price list on the pages read. Funds "expire one year after they are added". "Requests ending as failed or nsfw are not charged" (https://docs.higgsfield.ai/docs/concepts/billing-and-retention.md). Do NOT hard-code prices; UNVERIFIED for any specific model.
- Rate limits (https://docs.higgsfield.ai/docs/concepts/rate-limits.md): main limit is concurrency; your numbers are "in the Higgsfield Console", no fixed default published. Over-limit requests are accepted as `queued`; queue limit is "a multiple of your account's concurrency limit" (multiplier not stated). When the queue is full: `429` + `Retry-After`, body e.g. `{"code":"account_queue_full","retryable":true,"retry_after_seconds":30}`, "nothing is created or charged"; resubmit with the same `Idempotency-Key`. `503` `admission_control_unavailable` -> retry with backoff. Successful responses carry no rate-limit headers.
- Terms (https://higgsfield.ai/terms, "Last updated: October 23, 2026", read 2026-11-02): s4.4 "Company does not claim ownership of any of your Inputs or Outputs, nor does it restrict your commercial use of Outputs." s5.5 "Where required by applicable law, you will disclose that Output is artificially generated or manipulated." s6.4 Company may add watermarks/provenance but "does not warrant that any marking will be applied". s11.1 "Developer Access" covers "the API, MCP, CLI, or any other programmatic means"; s11.12 activity through Developer Access is treated as yours; s11.5 no sublicense/resell of Developer Access; s11.7 developers "shall not represent to End Users or third parties that Outputs are human-generated"; s5.2(iv) no using Service/Outputs to "train, fine-tune, distill" AI models (limited exceptions). s4.4 also says Company may use Inputs/Outputs "to train, develop, enhance, evolve, and improve its ... AI models" (Enterprise Agreement customers excluded): privacy note for users, since prompts are sent to Higgsfield. Help center: commercial rights "not tied to a specific plan"; free-plan watermarks are "embedded at generation"; "Paid plans include watermark-free downloads" (https://higgsfield.ai/creator-hub/help-center/account/who-owns-my-generations-and-can-i-use-them-commercially). I did not read the separate "Developer Terms" document; UNVERIFIED beyond what the main Terms s11 says.

## 3. ADOBE FIREFLY API (Firefly Services)

### 3a. Endpoints, auth, async model  [VERIFIED unless tagged]
- Quickstart https://developer.adobe.com/firefly-services/docs/firefly-api/guides/ (read 2026-11-02): token endpoint `https://ims-na1.adobelogin.com/ims/token/v3`; scopes `openid,AdobeID,session,additional_info,read_organizations,firefly_api,ff_apis`; image request `POST https://firefly-api.adobe.io/v3/images/generate-async`; headers `Content-Type: application/json`, `Accept: application/json`, `x-api-key: <client id>`, `Authorization: Bearer <access token>`. Sample prompt "a realistic illustration of a cat coding".
- Credentials: Developer Console project -> add API "Firefly - Firefly Services" -> OAuth Server-to-Server credentials ("Default choice for type of authentication is made for OAuth Server-to-Server") (https://developer.adobe.com/firefly-services/docs/guides/get-started). Token = `client_credentials` grant (client_id, client_secret, scope) POSTed to the IMS URL; token valid 24 h, Adobe recommends renewing every 23 h (https://developer.adobe.com/audio-video-firefly-services/getting-started, also quotes endpoint and a narrower scope `openid,AdobeID,firefly_api,ff_apis`). Token response field names (`access_token`, `expires_in`) are standard OAuth but I did not see Adobe's JSON: treat as UNVERIFIED.
- Async how-to https://developer.adobe.com/firefly-services/docs/firefly-api/guides/how-tos/using-async-apis : submit returns `jobId`, `statusUrl`, `cancelUrl`; poll `statusUrl` ("check once every second"); `status` is `running` while in progress, then `succeeded` or `failed`; on success `result.outputs[]` each with `seed` and `image.url` (a pre-signed URL). Expiry of the URL is not stated on that page; the OpenAPI shipped in Adobe's npm package `@adobe/firefly-apis@2.0.1` (https://unpkg.com/@adobe/firefly-apis@2.0.1/oas/FFApiOpenApi3.json) says "The pre-signed URL will expire in one hour" [package spec, not the docs page]. Download immediately.
- Changelog https://developer.adobe.com/firefly-services/docs/firefly-api/getting-started/changelog/ : Sept 10 2025 Generate Images v2 etc. removed; Oct 3 2025 non-async v3 APIs (Generate Images v3, ...) removed, "use the async versions"; Apr 29 2025 Image Model 4; Jun 19 2025 "Launch of Generate Video API". So only the async image endpoint is current.
- Image Model 5: usage notes (https://developer.adobe.com/firefly-services/docs/firefly-api/getting-started/usage-notes/) name "Image Model 5 endpoint `/v4/images/generate-async`"; the Image5 migration page (via search) says it is a breaking change (e.g. only `size`, no `aspectRatio`/`modelVersion`). Exact v4 request body: not verified (the live API reference is a JS-rendered page I could not read). Treat v3 body below as the safe baseline and pin the version in the connector.
- v3 generate body (from the SDK OpenAPI, `FFApiOpenApi3.json` v2.0.1): `prompt`, `negativePrompt`, `numVariations`, `seeds[]`, `size{width,height}`, `contentClass` (photo|art), `style`, `visualIntensity`, `promptBiasingLocaleCode`, `tileable`, `structure`. Output format selection: not confirmed.
- Video: `POST /v3/videos/generate` (SDK spec; changelog confirms launch 2025-06-19). Body: `prompt`, `negativePrompt`, `seeds[]` (only 1), `sizes[]`, `image` (keyframe), `videoSettings`, `bitRateFactor`; optional header `x-model-version` (SDK spec says only `video1_standard`). Returns `202` and a job (async, same status/cancel pattern). Supported ratios 16:9, 9:16, 1:1 (usage notes). The Firefly API Overview page (https://developer.adobe.com/firefly-services/docs/firefly-api/) does not list video. Whether partner video models (Veo, Kling...) are exposed via API: UNVERIFIED.
- Rate limits (usage notes): "Default limits apply per organization, with a daily cap of 9,000 requests", "4 requests per minute (RPM)"; exceeding -> `429`. (Page text as summarised by the fetch tool: re-read before quoting; the 9,000 figure may be a different limit scope.)
- Content Credentials: Adobe Firefly Services Security Fact Sheet, March 2025 (https://www.adobe.com/cc-shared/assets/pdf/trust-center/ungated/whitepapers/creative-cloud/adobe-firefly-services-security-fact-sheet.pdf; text extracted locally): "The Firefly API attaches a Content Credentials manifest to the generated content and saves this manifest to the Content Credentials cloud." Output stored in encrypted S3 behind a pre-signed URL; uploaded reference content is deleted after 24 hours. The fact sheet also says Firefly Services supports "OAuth Server-to-Server credential authentication". So API outputs come with C2PA/Content Credentials embedded in the file (and recoverable from the cloud); the connector must not strip them (see terms).

### 5. Firefly terms
- Adobe Generative AI Product Specific Terms, effective 2025-06-17 (https://wwwimages2.adobe.com/content/dam/cc/en/legal/servicetou/adobe-generative-ai-product-specific-terms-en-us-20250617.pdf; text extracted locally) [VERIFIED]: s3.1 "you must not remove or alter any watermarks or Content Authenticity Initiative metadata (e.g., Content Credentials) that may be generated with the Output, or otherwise attempt to mislead others about the origin of the Output." s3.2 "The Output may not be protectable by Intellectual Property Rights." s3.3 "No AI/ML Training": must not use Outputs "to directly or indirectly create, train, test, or otherwise improve any machine learning algorithms or artificial intelligence systems". The terms also refer to the Adobe Generative AI User Guidelines (https://www.adobe.com/go/adobe-gen-ai-user-guidelines), NOT read.
- Commercial use: "Outputs generated with Adobe Firefly AI models can be used for commercial purposes." (Firefly plans page, 2026-11-02). "Eligible enterprise customers can also receive IP indemnification for select Adobe Firefly outputs." (FAQ fragment). Beta features / non-Adobe partner models can have different terms (search summary of terms; not verified): check per model before shipping partner-model output.
- Labeling: no user duty to label AI content was found in Adobe's terms (absence only; UNVERIFIED that none exists). "Adobe automatically attaches Content Credentials for transparency" (plans page). Practical rule for Reelwright: keep the embedded Content Credentials in saved assets, record `provider/model/generated: true` in the manifest, and apply the repo's existing "Illustrative data"/disclosure rules. Note that re-encoding in a video render will drop file metadata; the terms forbid removing credentials "or otherwise attempt to mislead others about the origin". Whether compositing an Output into an mp4 counts as "removing" is a legal question: UNVERIFIED, flag for the user.

## 6. ADOBE EXPRESS
- No public generation API for individuals found. The Express REST API (https://developer.adobe.com/firefly-services/docs/express-api/guides/ , read 2026-11-02) "enables you to integrate Adobe Express functionalities into your applications through a REST API" but "currently only operate[s] on the Express documents tagged for automation workflows" (endpoints under `/beta/`, scope `ee.express_api`, needs Developer Console API key + token + a document tagged with the Tag Elements add-on). It automates templates/variations/renditions, not prompt-based generation, and lives under the Firefly Services docs. Prompt-based generation in Express is via the front-end Embed SDK `createImageFromText()` [SEARCH-ONLY]. Conclusion: confirmed that Reelwright needs no Express API; manual export-and-import only.
- Export formats [SEARCH-ONLY; the help pages returned 403 to my fetcher, summaries are from official helpx.adobe.com results]: PNG, JPG, PDF, MP4, GIF (GIF up to 60 s, no audio or transparency). MP4 size range 146x146 to 4096x4096 px (https://helpx.adobe.com/express/web/troubleshoot/performance-issues/download-export-stuck.html); "the maximum file size is 200MB" and no alpha for MP4 (https://helpx.adobe.com/express/web/bring-in-assets-from-other-apps/import-files-from-other-apps/export-formats-and-limitations-for-saving-projects-to-aem-assets.html, that is the AEM Assets export page, may differ for normal download). Use PNG when transparency is needed. Re-verify in a browser before documenting.

## 7. What a mocked test must mock (CI, no keys)

Design hint: put all HTTP behind one injectable `fetch`-like function (or `REELWRIGHT_GEN_MOCK=1` / a base-URL env override) so tests use a local stub server. Test content-hash cache hits (second `gen` run makes zero requests) and secret redaction in logs.

### Higgsfield REST (preferred connector transport)
1. `POST {base}/{model-path}` -- assert headers: `Authorization: Key <id>:<secret>`, `Content-Type: application/json`, `Idempotency-Key: <uuid>`; body e.g. `{"prompt": "..."}`. Reply 200 `{"status":"queued","request_id":"<uuid>","status_url":"{base}/requests/<id>/status","cancel_url":"{base}/requests/<id>/cancel","expires_after":604800}`.
2. `GET status_url` -- sequence: `{"status":"queued",...}` -> `{"status":"in_progress",...}` -> `{"status":"completed","request_id":..., "images":[{"url":"<stub>/img.png"}], "expires_at":"2026-..Z"}` (video: `"video":{"url":...}`).
3. `GET <output url>` -> image/video bytes (the real URL is an external CDN, so mock the download too).
4. Failure cases: terminal `failed` (with `"error"`), `nsfw`, `canceled`; `429` with `Retry-After` and `{"code":"account_queue_full","retryable":true,"retry_after_seconds":30}`; `503` `admission_control_unavailable`; `401/403` bad key (`403` + `code: api_key_disabled` for a disabled key).
5. Missing env vars -> clear error before any network call.
### Higgsfield CLI (alternative transport, only if the user wants plan credits)
Mock the child process: `higgsfield generate create <model> --prompt ... --wait --json` -> JSON with `id, job_type, status:"completed", result_url, params`; also exit codes for "Session expired"/"Not authenticated". Not CI-friendly because auth is a browser login; recommend REST for the connector and CLI only as a documented manual route.
### Firefly
1. `POST https://ims-na1.adobelogin.com/ims/token/v3` -- form-encoded `grant_type=client_credentials&client_id=...&client_secret=...&scope=openid,AdobeID,session,additional_info,read_organizations,firefly_api,ff_apis`; reply `{"access_token":"...","token_type":"bearer","expires_in":86399}` (shape assumed from standard IMS/OAuth: UNVERIFIED). Cache token ~23 h in memory.
2. `POST https://firefly-api.adobe.io/v3/images/generate-async` -- assert `x-api-key`, `Authorization: Bearer`; body `{"prompt":"...","numVariations":1,"size":{"width":2048,"height":2048}}`; reply 202 `{"jobId":"urn:ff:jobs:...","statusUrl":"<stub>/status","cancelUrl":"<stub>/cancel"}`.
3. `GET statusUrl` -- `{"jobId":..., "status":"running","progress":50}` -> `{"status":"succeeded","result":{"outputs":[{"seed":123,"image":{"url":"<stub>/out.jpg"}}]}}`; and `{"status":"failed",...}`.
4. `GET <presigned url>` -> bytes. Optionally embed a tiny fake C2PA marker and assert the saved file's bytes are written unmodified (never re-encoded).
5. Failures: `401` expired token (refresh once), `403` no entitlement, `429` (4 RPM default: backoff), `400` content-policy rejection.
6. Video (if ever added): `POST /v3/videos/generate` -> 202 job, same polling, result with `video.url` [shape of `VideoOutput`: `seed`, `video`].
